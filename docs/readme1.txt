# Описание проекта
Бот для верифицированного голосования в телеграм-группах.


## Роли участников
- Пользователь (user)
  - просто пользователь, воспользовавшийся ботом. Не имеет никаких статусов, записанных в БД. Этот статус присваевается автоматически при взаимодействии с ботом.
  - может пройти регистрацию и стать участником в случае одобрения заявки.
- Кандидат (сandidate)
  - пользователь, прошедший процедуру регистрации в группе, но пока не получивший одобрение администрации.
  - Не может голосвать или участвовать в управлении группой.
- Участник (member):
  - Может пройти регистрацию и получить право голоса
  - Может голосовать за тот или иной вариант в идущем голосовании, может менять выбранный вариант в ходе голосования.
  - Может выбирать Представителя. Может менять Представителя.
  - Может стать Представителем.
- Представитель (proxy):
  - Может голосовать за себя и своих "подписчиков" (тех, участников, кто его выбрал но не проголосвал сам)
  - Может делать рассылку через бота своим "подписчикам"
  - Может "уйти в отставку"
  - Может стать Делегатом (если получит больше определенного числа "поlписчиков")
- Делегат (delegate):
  - Обладает правами Представителя
  - Может создавать голосование
  - Может добавлять к голосованию варианты решений (пока действует период добавления)
- Регистратор:
  - Может верифицировать участников
- Администратор:
  - Может запускать и завершать голосования и их этапы.
  - Может назначать регистраторов.
  - Может удалять голосования и варианты решений.
- Владелец:
  - Обладает правами админстратора.
  - Может менять (добавлять и удалять) статусы пользователей.

Участники могут совмещать несколько ролей.

## Процесс регистрации
За регистрацию отвечают хэндлеры, собранные в модуле handlers\reg_process_handlers.py.
Это самая упрощенная версия регистрации. Есть другие версии этого файла в папке handlers\registration_variants
В одной добавляется просьба прислать телеграм-контакт (что дает номер телефона, к которому привяза аккаунт).
В другой выясняется адрес кандидата вплоть до многоквартирного дома или диапазона домов в частном секора.
Столь подробная версия может потребоваться для местных сообществ или для клубов избирателей в определенном округе.
В самой упрощенной версии кандидату присылается текст с просьбой ответить на какие-то вопросы. Этот текст составляет
владелец группы, он может быть изменен в любой момент.

## Голосования
Голосования прохлодят в несколько этапов.
1. Создание голосования:
- Создает делегат.
- Добавляет название и описание.
2. Добавление вариантов :
- Любой делегат может добавить варианты.
- Ограничений на количество вариантов пока нет.
3. Голосование :
- Участники голосуют за варианты.
- Если участник не голосует, его голос передается представителю.
- Участник может переголосовать в любой момент, пока голосование идет.
4 Промежуточный этап :
- Менее популярные варианты исключаются.
- Участники, голосовавшие за них, выбирают из оставшихся.
5. Финальный этап :
- Исключаются все варианты, кроме двух самых популярных. В случае невероятного совпадения равенства по всем показателям 2-го и  3-го маста в финальный этап выходят три варианта.
6. Завершение голосования:
- Остается один вариант. Если он набрал более 50% решающих голосов (имеющихся в группе в целом), этот вариант становится победителем, голосование завершается.
7. Утверждение итогов:
- Если число поданных за вариант-победитель голосов менее 50% от числа имеющих права решающего голоса автоматически запускается голосование с двумя вариантами - победителем и вариантом "лучше не принимать никакого решения".
8. Завершение утверждения итогов:
- Если вариант-победитель набрал больше варианта "лучше не принимать никакого решения", он становится победителем. В противном случае побеждает вариант "лучше не принимать никакого решения".

### Статусы голосований
add_variants - голосование в стадии добавления вариантов.
ongoing - идущее голосование (от начала, во всх промежуточных этапах и в финале). Статус меняется автоматически в момент старта голосвания.
confirmation - утверждение итогов
completed - завершенное голосование

### Статусы вариантов
valid - действительный вариант
invalid - недействительный вариант. Вариант становится invalid если администратор его удалил.
loser - проигравший вариант (на промежуточном этапе, при переходе в финал или при завершении голосования)
winner - победивший вариант

### Статусы голосов (пользователей за варианты)
valid - действительный голос, только он считается при подсчетах результатов голосования.
invalid - недействительный (например, после того, как пользователь проголосовал за другой вариант). Далее не учитывается в подсчетах, но сохраняется в БД.
lose - голоса, отданные за проигравший вариант и имевшие на момент проигрыша статус valid. Не учитываются при дальнейших расчетах но сохраняются "для истории".
win - голоса, отданные за вариант-победитель и имевшие статус valid в момент завершения голосования (хотя можно было бы просто оставить valid)

# Описание базы данных
Пока используется SQLite
Логика БД состоит в том, что использовать ее могут разные платформы (не только телеграмм-боты). А также на одной БД могут находиться несколько групп, некоторые из которых являются подгруппами. Любой член подгруппы автоматически является членом материнской группы (но не наоборот).
В будущем будет опция слияния групп (создания на базе двух групп материнской). И опция создания подгруппы. Пока бот будет писаться в логике работы одной-единственной группы, но для сохранения возможностей будут сразу созданы необходимые таблицы. Пока на каждую группу (в БД) – свой бот.

## Таблица Users
Таблица всех пользователей всех групп, которые входят в данную БД.
Профиль юзера. Поля:
id,
телеграм id,
телефон,
тг-имя,
тг-фамилия (предыдущие 4 поля добываются из карточки контакта),
Имя.
Отчество,
Фамилия,
дата рождения
год рождения (на случай если день и месяц не спрашиваем),
фото,
e-mail
tg_username - псевдним в телеграм
username - псевдоним в группе(ах)
tg_available - доступность для телеграм бота (если None или пустая клетка - доступен)
В реальности может использоваться только id

## Таблица Members
Таблица членов группы.
Список полей:
- id
- группа-id (здесь и далее – наличие ‘id’ в конце названия ознаает внешний ключ)
- юзер-id (внешний ключ)
- представитель, которого выбрал член (тоже участник этой группы)
- количество голосов (опция для будущего, например, ТСЖ)
- описание (опция для представителей, но наверно и сами участники могут что-то про себя написать)
- resume - резюме, которое прислылает пользователь при вступлении в группу (если проедура регистрации это предусматривает)

## Таблица Clubs
Таблица групп.
Группа должна иметь уникальное название. Также она может иметь описание, ссылку на какой-то ресурс. Группы могут быть материнские и дочерние. Каждый член дочерней группы является членом материнской.  tg_bot - название и ID бота, обслуживающего группу.
Поля:
- id
- name
- description
- father_group (внешний ключ на саму таблицу Clubs). "Материнская группа".
- tg_bot (текстовое поле)

## Таблица Status
Таблица статусов участников.
Один участник может иметь несколько статусов. Каждый статус дает какие-то права.
Поля:
- id
- member_id (внешний ключ)
- status (текстовое поле)

## Таблица Tokens
Уникальные токены, которые выдаются пользователям для регистрации или подтверждения каких-то действий. Указывается создатель токена (обычно это админ или модератор).
Поля:
- id
- token – неповторяющийся набор символов, который может выдаваться пользователям для подтверждения идентичности
- club_id - группа, для которой выпущен токен (в принципе, вычисляется через креатора)
- creator - создатель токена (обычно админ или модератор)
- status - статус, который присваивется пользователю после введения токена
- validity - срок годности самого токена (после какой даты перестает приниматься)
- time_of_action - время действия прав, которые дает токен
- number_of_possible - число пользователей, которые могут воспользоваться токеном
- sity - город (здесь и далее - информация, которая может быть привязана к токену, например, по месту его распространения, могут быть использованы поля частично или вовсе не использованы)
- district - район города
- street - улица
- house - номер дома
- entrance - номер подъезда
- apartment - номер квартиры
- telephon_number (здесь и далее информация, которая привязана к конкретному получателю токена при выдаче токена, может быть подтверждена пользователем при регистрации)
- first_name - имя
- lust_name - фамилия
- polling_station - номер избирательного участка
- lot - номер партии токенов (когда их печатают оптом)
- number_in_lot порядковый номер токена в партии

## Таблица Registrations
Журнал регистраций.
- object_type - тип объекта регистрации (чей статус поменяли)
- object_id - ID объекта регистрации
- registrator - кто зарегистрировал (member_id)
- token_id - если при регистрации использовался уникальный токен
- status - какой статус был присвоен в результате регистрационной записи. Если статус был снят - not_(status)

## Таблица Links
Таблица используемых участниками и группами ссылок (в своих описаниях, голосованиях и вариантах).
Поля:
- id
- link_href
- link_title
- link_text (атрибуты ссылки)
- member_id (используется, если ссылку использует какой-то участник, например, предсставитель)
- vote_id (если ссылка используется при создании голосования)
- variant_id (если ссылка используется в описании варианта)
- user_id (если ссылка используется в профиле юзера, например, его соцсети - опция на будущее)
- club_id (если ссылка используется в описании группы)

## Таблица Votings
Таблица голосований. Одна строка - одно голосование.
Поля:
- id
- creator - создатель (из числа участников чата)
- vote_type - тип голосования
- title - название голосования
- text - текст объяснения что-за голосование и зачем
- club_id - id группы в которой проходит голосование
- voting_status - статус голосования (идет сбор вариантов, идет голосование, завершилось, стадия утверждения голосования)
                                               ('add_variants','ongoing','completed','confirmation')
- time_create - время создания
- time_start - время старта голосования за варианты
- time_complete - время завершения
- result - вариант, победивший в голосовании (внешняя ссылка на таблицу вариантов)
- directly_votes REAL, - голоса, отданные за вариант учстниками с правом решающего голоса напрямую
- proxy_votes    REAL, - голоса, отданные за вариант участниками с правом решающего голоса через представителей
- empty_votes    REAL, - голоса, отданные участниками без права решающего голоса напрямую

## Таблица Variants
Вариант решения для голосования. Предполагает короткое название title, текст решения text, ссылка на разъяснение link (или на полный текст, если он не влез в ограничения)
Поля:
- id
- vote_id
- author - создатель варианта (вешний ключ на Members)
- title - название
- text - текст
- time_create - временная метка (момент создания)
- variant_status - статус варианта. Если он "проиграл" и выбыл из голосования - "loser", при создании - "valid", победитель - "winner"

## Trusts
Журнал фиксации доверия голосов (фиксируется когда какой пользователь выбрал представителя или сменил представителя)
id
member_id - кто доверил голос
proxy_id - кому доверил
time_trust - время доверия

## Elections
Журнал подачи голосов полльзователями
id
member_id - кто проголосовал
variant_id - за какой вариант проголоовал
time_election - время подачи голоса
status - текущий статус выбора. При создании - 'valid' (если пользователь позже проголосовал за другой вариант, меняется на 'invalid')
